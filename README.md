# 订单交付分析 · 准时率与归因

一个纯本地的订单交付分析网页工具：导入最初承诺、每次改期、分批发货、签收与取消记录，
按**最初承诺**与**当时有效承诺**两套口径并列计算准时率，部分交付同时按**数量**与**订单**
两套口径展示；归因只使用有记录的原因证据，没有依据的部分一律列为**未解释**，绝不自动猜测。

零依赖（无构建、无 npm 包），全部计算在浏览器本地完成，数据不出本机。

## 运行

方式一（推荐，避免个别浏览器对本地文件的限制）：

```bash
cd 本目录
python3 -m http.server 8000
# 打开 http://localhost:8000
```

方式二：直接双击 `index.html`（经典脚本 + 本地文件读写，file:// 下可用）。

首次打开自动载入**虚构示例数据**（14 单，覆盖拆单、取消后恢复、跨时区签收、分批发货、
无原因改期、逾期未交付等情形）。点「导入 JSON」换成自己的数据；「导出 → 数据 JSON」
可导出当前数据（含补录记录）作为模板。

## 功能地图

| 需求 | 位置 |
|---|---|
| 双口径准时率（初诺 / 当时有效承诺） | 总览 → KPI 行 + 口径对照矩阵（差额=改期掩盖幅度） |
| 部分交付：数量 / 订单两套口径 | 口径对照矩阵两行；订单页每单两列判定 |
| 归因只用记录证据，无依据列未解释 | 归因页：分段条 + 分类表 + 明细；订单详情 → 归因分解 |
| 展开一单的承诺时间线 | 订单页 → 展开 → 时间线图 + 承诺链（含每次改期的记录原因） |
| 对比团队或物料 | 对比页：条形图 + 全指标表，点击行/条钻取 |
| 补入迟到签收后重算 | 订单详情底部「补录签收」：时间+时区+数量+可选原因，提交即全量重算 |
| 每次口径/数据变化的差额 | 重算记录页：每次导入/补录/删除的快照与逐项差额；toast 即时提示 |
| 指标钻取到明细 | KPI 卡、归因分类、对比组均可点击钻取到订单列表 |
| 导出 | 工具栏：明细 CSV / 指标 CSV / 数据 JSON（均可再导入） |

## 数据格式

```jsonc
{
  "meta": {
    "name": "数据集名称",
    "asOf": "2026-04-05T18:00:00+08:00"   // 数据截止时间；缺省取全数据最新事件
  },
  "orders": [
    {
      "id": "SO-1001",
      "customer": "客户", "team": "团队", "material": "物料",
      "qty": 120, "unit": "台",
      "tz": "Asia/Shanghai",              // 订单时区（IANA），准时判定按此时区的日历日期
      "splitFrom": "SO-1000",             // 可选：本单由哪单拆出
      "splitInto": ["SO-1001A"],          // 可选：本单拆出了哪些子单
      "events": [
        { "type": "promise",    "at": "2026-01-05T09:00:00+08:00", "promiseDate": "2026-02-10" },
        { "type": "reschedule", "at": "2026-01-28T10:00:00+08:00", "promiseDate": "2026-02-18",
          "reason": { "category": "material_shortage", "detail": "芯片缺货", "evidence": "PO-8842" } },
        { "type": "shipment",   "at": "2026-02-09T15:00:00+08:00", "qty": 60, "shipId": "SH-1" },
        { "type": "receipt",    "at": "2026-02-10T11:20:00+08:00", "qty": 60, "shipId": "SH-1" },
        { "type": "cancel",     "at": "2026-01-25T11:00:00+08:00", "qty": 20,
          "reason": { "category": "other_recorded", "detail": "客户砍单" } },
        { "type": "restore",    "at": "2026-02-01T10:00:00+08:00", "qty": 20 }
      ]
    }
  ]
}
```

- **事件类型**：`promise`（最初承诺，每单恰好一个）、`reschedule`（改期）、`shipment`（发货）、
  `receipt`（签收）、`cancel`（取消）、`restore`（取消后恢复）。
- **`at`**：带时区偏移的 ISO 时间戳（事件发生的真实时刻，可跨时区，如 `2026-02-10T17:30:00-08:00`）。
- **`promiseDate`**：`YYYY-MM-DD`，订单时区下的承诺日历日。
- **`reason.category`** 只能是：`material_shortage` 缺料 / `customer_reschedule` 客户改约 /
  `transport_exception` 运输异常 / `capacity_shortage` 产能不足 / `quality_hold` 质量暂扣 /
  `other_recorded` 其他（有记录）。**不写 reason 即计入"未解释"**；未知分类会被丢弃并产生校验警告。
- 补录的签收会带 `backfilled: true` 与 `uid`，可导出再导入。
- 导入时全量校验（数量守恒、时区合法、拆单引用、超收等），问题以警告展示、不阻断。

## 口径定义（页面底部「口径说明」同文）

- **准时判定**：签收时间换算到**订单时区**后的日历日期 ≤ 承诺日期。
- **最初承诺口径**：与第一张承诺单比较；**当时有效承诺口径**：与该签收时刻**已生效**的
  最后一次承诺比较——签收之后才登记的改期不算数，避免用最后一次改期掩盖原始延期。
- **数量口径** = 按时签收数量 ÷ 到期有效数量；**订单口径** = 整单交齐且交齐那张签收单准时的订单数 ÷ 到期订单数。
- **有效数量** = 订购 − 取消 + 恢复；全部取消、未到期（最终承诺日 ≥ 数据截止日且未交齐）的订单不计入分母；超收不计入分子。
- **归因**：总延期（签收日 − 最初承诺日）拆为「每次改期的位移」+「签收日 − 当时承诺日」残差，
  各段只认记录中的原因（改期记录的原因；残差认签收/发货记录的原因），无记录即未解释；
  各段之和恒等于总延期（可为负，表示提前）。逾期未交付数量同样分解，其残差一律未解释。
